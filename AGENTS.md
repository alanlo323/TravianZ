# TravianZ

## Purpose

TravianZ v11 is an open-source browser strategy game in the classic Travian style. The web root is a set of procedural PHP page scripts. Game rules live in `GameEngine/`, HTML views live in `Templates/`, and a small `App\` layer under `src/` holds newer helpers. The supported runtime is PHP 8.3+ with MariaDB. `GameEngine/config.php` is generated by the installer and is not in git.

## For AI Agents

### Working In This Directory

- Page scripts at the web root include `GameEngine` classes and then a `Templates/*.tpl` view. Change the engine and the template together when a screen's data shape changes.
- Keep the license banner at the top of existing PHP files. The project treats that notice as required.
- `GameEngine/config.php` is generated. Do not commit it. Read constants from a local install or from `install/data/constant_format.tpl`.
- New player-facing strings go in `GameEngine/Lang/en.php` and the matching locale file. Do not add translations only inside a template or page script.
- `MYSQLi_DB` and `Automation` are facades. New query or tick behavior belongs in the matching trait under `GameEngine/Database/` or `GameEngine/Automation/`, then the trait must be `include_once`'d and `use`d by the facade. Traits are global and are not autoloaded.
- `App\` classes autoload from `src/`. GameEngine classes stay in the global namespace.
- Tribe ids: Romans `1`, Teutons `2`, Gauls `3`, Nature `4`, Natars `5`, Huns `6` (units `u51`–`u60`), Egyptians `7` (`u61`–`u70`), Spartans `8` (`u71`–`u80`), Vikings `9` (`u81`–`u90`). Constants are `TRIBE1`–`TRIBE9` in `GameEngine/Lang/en.php`. Unit index base is `(tribe - 1) * 10 + 1`. Great-building training queue ids are offset by `+500`.
- Building ids (`gid`) run through the classic set and the v11 additions `42`–`50` (Hospital family, Great Workshop, Command Center `44`, tribe walls).
- Gold, troop, market, hero, and culture-point changes are race-sensitive. Keep amount checks server-side and non-negative. Do not trust a client user id for friend-list or similar ownership checks.
- Admin POSTs must keep CSRF checks from `GameEngine/Admin/csrf.php`.
- Client IP for bans comes from `App\Utils\IpResolver`. Trust `X-Forwarded-For` only when `REMOTE_ADDR` is in `IP_TRUSTED_PROXIES`.
- Many folders contain `index.php` that only blocks directory listing. Those files are not routers.
- Docker host port in `docker-compose.yml` is `8090`. The README quick start still says `8080`.

### Testing Requirements

- `./scripts/check.sh php` runs `php -l` on tracked `*.php` and `*.tpl` files (except `install/data/constant_format.tpl`) and executes every `tests/**/*Test.php`.
- `./scripts/check.sh test` also runs shell contract tests. `./scripts/check.sh compose` needs Docker.
- CI (`.github/workflows/quality.yml`) runs the PHP job on 8.3, 8.4, and 8.5, plus Compose validation.
- Tests are plain PHP scripts, not PHPUnit. A new test must be runnable with `php tests/.../FooTest.php` and must not need a database unless the existing suite already does.
- There is no browser test harness in the repo. UI changes need a manual pass through the affected page after install.

### Common Patterns

- Globals `$database`, `$session`, `$village`, `$generator`, `$building`, `$technology` are the usual in-request services.
- One resource tick should write one village `UPDATE`. Do not reintroduce a second write in `Village`.
- Build requirements belong in the declarative table in `Building.php`, not in a new ad-hoc `if` chain.
- After a mutation, call the central cache invalidation path (`invalidateCachesFor()`) instead of clearing one cache by hand.
- SQL must go through `MYSQLi_DB` helpers. Table names use the configured prefix.
- Templates are PHP-in-HTML (`.tpl`), included from the page script. They read the same globals.

## Dependencies

### Internal

- `GameEngine/Database.php` is included by almost every page via `Village.php` or `Generator.php`.
- `cron.php` is what actually runs `Automation.php` in production. Page requests must not start a second automation pass while `GameEngine/Prevention/cron_active.txt` is fresh.
- Installer output is `GameEngine/config.php`, `var/installed`, and rows created from `var/db/struct.sql`.

### External

- PHP 8.3+ with `mysqli`, `pdo_mysql`, `gd`, and `zip`
- MariaDB (or MySQL-compatible) with `sql_mode` empty in the Compose service
- Apache or nginx with rewrite
- No Composer project and no npm toolchain
